# 構図パターンとオリジナル規則

## 基礎構造タイプ

1つ選ぶ。混ぜすぎない。

### Workflow フロー

向く内容: 入力 → 処理 → 出力、コンテンツ制作、AI ワークフロー、自動化チェーン。

描き方: 左に入力、中央で小黒または怪機械が処理、右に出力。橙の矢印で主流を示す。

### システム局部

向く内容: 情報源、フィルタ、データベース、レンダラ、agent の局部。

描き方: 核心モジュールは 3–5 個だけ。小黒はうち1つの鍵動作に関わる。

### 前後対比

向く内容: 混乱/整然、手動/自動、分散/収束、不安/安定。

描き方: 左はぐちゃ、右は安定、中央に橙矢印。役割は少し誇張してよい。

### 役割状態

向く内容: ユーザーの痛み、作り手の状態、道具過多、情報不安、詰まりから動き出すまで。

描き方: 状態は 2–4。各状態に短い注記を1つ。

### 概念メタファー

向く内容: コンテンツ工場、情報倉庫、脳内ブラックボックス、ワークフロー機械、自動日報。

描き方: 大きな怪物件または機械を1つ。入力は少数、出力は1つ。記憶に残る形にする。

### 方法分层

向く内容: 方法論フレーム、システム階層、能力スタック、コンテンツシステムの層。

描き方: 箱を層に積む。正式なピラミッドにしない。小黒は横で運ぶ／組み立てる。

### 地図ルート

向く内容: 着想から公開まで、ユーザ経路、コンテンツの受け渡し、学習路。

描き方: 曲がった道1本、ノードは少数。小黒が線を引くか歩く。

### 小漫画分鏡

向く内容: 失敗→成功、実際の過程、ツッコミ、使用前後の変化。

描き方: 小シーン 2–4。1コマ1動作。

## オリジナルメタファー生成法

毎回、その文章からメタファーを発明する。旧図の流用はしない。

### 三步

1. 抽象概念を物理動作に換える: 詰まる、漏れる、重くなる、仕分け、沈殿、発酵、門を開ける、折る、開封、流れ戻る。
2. システム構造をローテク物件に換える: 壊れた機械、紙箱、引き出し、水管、郵便受け、変な文字盤、秤、井戸、梯子、変な作業台。
3. 小黒にその動作を担わせる: 横立ちではなく、機械に嵌る、線を引き違える、門番、運搬、修理、計量、梯子を支える、記録、怪装置に詰め込む。

### 使える物件プール

- 紙箱、引き出し、古い機械、漏斗、秤、郵便受け、門、井戸、梯子、水管、糸だま、水門、ターンテーブル、黒箱、パンチ、製麺機、物干しロープ、変な作業台。
- 使うときは 1–2 個だけ。詰め込まない。

### 小黒の動作プール

- 引く、担ぐ、詰める、掬う、押す、量る、縫う、切る、捻る、守る、受ける、分解する、印を付ける、回収する。
- 動作は核心の意味に奉仕する。怪のためだけの怪にしない。

## 复刻禁止

`assets/examples/` をデフォルトで開いたり、そのまま复刻したりしない。これらの画像は作風キャリブ専用（線の密度、余白、色の抑制、小黒の気配）。

ユーザーが明示的に「この構図で／このケースを复刻／この図を改変」と言わない限り、次の旧構図を直接再利用しない:

- コンベアの二つの断点
- コンテンツ機械の中で小黒が判断レバーを引く
- 小黒が漏斗になって流量／信頼／転換を仕分ける
- 小黒が素材の魚を切る
- 小黒が受け渡し経路を引く
- 小黒が三層の情報源を引く
- 三人の小黒がそれぞれメガホン／橋架け／門を開ける
- 小黒が話術ツール箱に押印する
- 小黒がよくある罠の経路を看板で見る

同テーマでもメタファーは新しくする。例: 「受け渡し経路」は必ずしも道ではなく、小黒がコンテンツの尾をドアノブに繋ぐでもよい。「一魚多吃」は必ずしも魚ではなく、小黒が一つの紙団子を何形かに押し出すでもよい。
