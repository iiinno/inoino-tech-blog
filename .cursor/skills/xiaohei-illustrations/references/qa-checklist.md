# QA Checklist

## 必過

- 16:9 横版である
- 背景はきれいな白地
- 小黒がいる
- 小黒が核心動作を担っている（飾りではない）
- 旧例の構図コピーではなく、その文章向けの新しいメタファーになっている
- 画面が怪誕で、創意があり、おもしろい
- 簡潔で清涼、主体は画面の約 60% 以下
- 1枚は1つの核心構造だけ
- 日本語注記は少なく・短く・読める
- 橙は主経路または矢印だけ
- 赤は重点・問題・注意・結果だけ
- 青は補足・フィードバック・システム状態だけ

## 失敗シグナル

次があれば再生成または局部編集:

- 左上に「よくある罠 / Workflow / システムアーキ図 / ルートマップ」系タイトル
- 小黒がマスコット・スタンプ・かわいい卡通化
- PPT・课件・正式フローチャート感
- 要素・矢印・ノード過多
- 注記が長文の説明になっている
- 背景に紙紋・影・グラデ・米色・ノイズ
- 実UIスクショやテック感UI
- 日本語の酷い化け・読めない注記
- 画面が固く、怪誕メタファーがない
- `assets/examples/` の旧例構図に酷似

## 反復方法

- 普通すぎる: 小黒を動作主体にし、奇抜だが成立するメタファーを足す
- 複雑すぎる: ノードを削り、動作1つと短い注記 3–5 に絞る
- かわいいすぎる: deadpan、blank serious expression、not cute、not mascot を強調
- PPTすぎる: タイトル・枠・整列グリッド・矢印過多を消し、手描きシーンにする
- 旧例に近い: 核心は残し、主物件と小黒の動作を換える
- 文字ミス: まず局部編集。多いなら再生成し注記数を減らす

## 交付判断

よい図は、先に「ちょっと変」と感じ、1秒で構造が分かる。

第一印象がチュートリアルページで、白紙上の怪誕プロダクトスケッチに見えなければ不合格。
