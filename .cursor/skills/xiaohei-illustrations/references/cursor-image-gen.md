# Cursor 画像生成メモ（いのまさ用）

調査時点の実務メモ。Skill の挙動はこの前提で書く。

## 仕組み

- Agent が `GenerateImage` を呼ぶと、**チャットモデルとは別の画像パイプライン**が動く
- 自分で「画像モデル」を Models 設定から選ぶ必要はない
- Ask / Plan モードでは使えない → Agent でやる
- テキスト or 参照画像（`reference_image_paths`）でガイドできる
- `aspect_ratio` は `"1:1" | "4:3" | "3:4" | "16:9" | "9:16"`（小黒は常に `16:9`）

## 保存

- ツール側はだいたいプロジェクトの `assets/` に置く
- この Skill では最終成果を Vault へコピーする:
  `C:\Users\inoue\Documents\obsidian_MyNotebook\Cursor\assets\<slug>-illustrations\`
- ホーム直開きでも動くことがあるが、成果物管理のため **Vault or プロジェクト** に寄せる

## 品質の現実

- 日本語手書きは短語なら実用レベル（スモーク: 「思考／詰まる／流れない」は読めた）
- 長い注記・多いラベルほど化けやすい → **少なく短く**
- スタイルはプロンプト + 必要時のみ例画像参照で安定させる
- 生成後は必ず画像を見て QA（説明文だけ信じない）

## つまずきやすい点

- 401 / 利用不可 → アカウント・一時障害。再試行し、だめなら報告して止める
- Auto ルーティングでツール非対応モデルに寄ると失敗することがある → 対応モデルで Agent
- タイムアウトや 429 はフォーラムでも報告あり → 枚数を分けて再試行
- チャットモデルの「ネイティブ画像生成」とは別物。Gemini/GPT を選んでも画像側は別経路

## この Skill での使い方要約

1. shot list → 確認（任意）
2. 枚ごとに GenerateImage（16:9）
3. Read で QA
4. Vault にコピーしてパス報告
